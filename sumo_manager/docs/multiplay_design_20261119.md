# マルチプレイ(2 台の iPad)設計案 2026-11-19

## しくみ
- 「親」の iPad が世界を作り(実名スタート)、計算もする。「子」の iPad は合言葉で参加して、親が選んでいない部屋を受け持つ。
- データの受け渡しは GitHub の Gist(小さなファイル置き場)。ゲームが API で直接読み書きする。
  - Gist の中身:世界のデータ(圧縮。始め 0.7MB → 圧縮後 0.2MB ほど、10 年後 1.4MB → 0.3MB)、子の指示(稽古・作戦・勧誘・出来事の答え)、ふたりの「準備できた」。
  - API は 1 ファイル 1MB までしか返さないので圧縮して送る。鍵ありで 1 時間 5,000 回まで(5 秒ごとに確かめて 720 回)。
- 進め方:Football Manager のネットワーク対戦と同じ。ふたりとも「準備できた」を押すと、親が 1 週間(本場所は 1 日)計算して書き込み、子は数秒ごとに読みにいく。10 分たつと、押していない側は前の週と同じ設定で進む(案)。

## 段階(今のゲームは「プレイヤーは 1 人」の前提が 250 か所以上あるため)
1. **第 1 段階**:子の部屋は「稽古・作戦・新弟子の勧誘」を子が決める。お金・スタッフ・施設は、ほかの部屋と同じく自動で回る。つなぐ画面と「準備できた」の画面。
2. **第 2 段階**:子の部屋にもお金・スタッフ・施設・出来事を持たせる(プレイヤーごとのデータに分ける作り直し)。
3. **第 3 段階**:通信が切れたときや iPad が眠ったときの扱い、ふたりの記録の比べ合い。

## 見本
- mp0:つなぐ設定(鍵・親になる・合言葉で参加)
- mp1:上に対戦の帯(ふたりの状態)+「準備できた」ボタン
- mp2:ふたりの部屋を並べたカード+「準備できた」
見本の作り方は `tools/mkmpsamples.py`。

## 鍵(トークン)の作り方(ダルマさん用)
GitHub の画面は変わることがあるので、名前が少し違うときは近いものを選んでください。
1. Safari で github.com にログインする。
2. 右上の自分のアイコン → 「Settings」→ 左の下のほうの「Developer settings」。
3. 「Personal access tokens」→「Tokens (classic)」→「Generate new token」→「Generate new token (classic)」。
4. 「Note」に「sumo」、「Expiration」は 90 日など。
5. チェックは **「gist」だけ** に付ける(ほかは付けない)。
6. いちばん下の「Generate token」を押す。`ghp_` で始まる文字が 1 回だけ表示されるので、コピーしてメモ帳などに控える。
7. ゲームの「ふたりで遊ぶ」の画面で、2 台の iPad それぞれに貼りつける(ゲームのファイルには書かない。iPad の中だけに保存)。
- 注意:この鍵があると、ダルマさんの Gist を書きかえられます。人に見せたり、公開の場所に貼ったりしないでください。不要になったら同じ画面で削除できます。
