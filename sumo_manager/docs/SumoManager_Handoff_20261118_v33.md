## 1. 進め方の決まり

1. Claude が設計案を書く → ダルマさんが「実施」と返す → 実装する。
2. 実装は必ず新しい版のファイルとして作る(古い版は上書きしない)。
3. 実装後は自動テストをする。
   - 40 年(240 場所)の自動プレイで、エラーと数値の偏りを測る。
   - 画面は iPad 横(1180×820)・iPad 縦(820×1180)・スマホ(390×844)の 3 サイズで、エラーと横あふれを確認する。
   - 1 つ前の版の保存データが引き継げるかを確認する。
4. リアルさを最優先にする。ゲームが難しくなってもよい。
5. 実在の規則・数値は、実装前に検索して今の内容を確かめる。
6. **画面の見た目や操作を変えるときは、必ず先に見本(`samples/` の HTML と画面の写真)をダルマさんに見せ、どれにするか決めてもらってから実装する。**(2026-11-17 に決めた決まり)

### 3.8 師弟の信頼と部屋の人間関係(設計 16)
- 信頼(`r.tr`、0〜100)の効き目:70 以上で稽古の伸び +5%、30 未満で −8%(`shF`)。関取からのお礼は信頼で関取収入の 3〜8%(`ownGift`)。

- 接し方(`r.sh`:褒める/ふつう/厳しく):厳しくは伸び +3%(負けず嫌い・野心家は +8%)、繊細・気分屋は信頼と気力が下がる。褒めるは信頼が上がり、伸びは −2%(おっとり・繊細は +3%)。
- 兄弟子(`r.ani`):入門 2 年以内(`isNewbie`、初期の実在力士は対象外)に自動で付く。1 人の兄弟子に 2 人まで。兄弟子の信頼が弟弟子に伝わる。
- 部屋の雰囲気(`atmo`)は信頼の平均で、部屋頭は 2 倍の重み。
- 入門 2 年以内の廃業(`v13Basho`):場所ごとの確率 =(0.022 + 0.02×(50−信頼)/30 + 0.01×(50−雰囲気)/30 − 兄弟子の信頼 60 以上なら 0.004)×(1 年目 1.3/2 年目 0.7)、性格で補正、0.3〜8%。信頼 28 未満なら半分は相談なしで部屋を出る。それ以外は「辞めたいという相談」(引き留める/親を呼ぶ/送り出す)。参考:実際は 2 年で約 3 割が辞めるという資料あり(職業ガイドの記述で、公式の統計ではない)。
- けがを隠す:信頼 35 未満で中程度のけが(「けがは休場」の方針なら軽傷も)のとき、場所前に隠して出場することがある。場所後に発覚し、全治が延びて重くなることがある。
- 兄弟子の暴力の芽:雰囲気 48 未満で、兄弟子が豪快・負けず嫌い・信頼 40 未満だと起きやすい。親方が気づけば「兄弟子と弟弟子」の出来事(協会に報告/部屋の中だけで指導/様子を見る)。気づかない・報告しないと、1〜3 場所後に不祥事として発覚し、監督責任で評判が下がる。2018 年 10 月の「暴力決別宣言」に沿って、親方が手を上げる選択肢は作らない。
- 弟子からの相談(`soudan`):家族の事情、両親の来訪、伸び悩み。
- 親方の評判(`G.jin`):雰囲気に引かれて動き、相談・送り出し方・不祥事で上下する。勧誘の成功率に ±最大 0.1(`offerP`)。
- 引退後:名跡の資格があっても信頼 35 未満なら部屋に残らない。70 以上なら「恩を返したい」と申し出る。引退の相談に「第二の人生を一緒に考える(10 万円)」を追加。

## 7. 開発メモ

- 作り方:前の版の HTML に Python のパッチスクリプト(`patchN.py`)で文字列置換を当てて、新しい版を作っていた。置換対象は一致数をチェックしている。v13 は `patch16.py`(v12 → v13)、v14 は `patch17.py`(v13 → v14)、v15 は `patch18.py`(v14 → v15)、v16 は `patch19.py`(v15 → v16、名跡データは `myo2026.txt`)、v17 は `patch20.py`(v16 → v17、部屋データは `heya2026.txt`)、v18 は `patch21.py`(v17 → v18、データは `toshiyori2026.csv`・`ura2026.txt`・`rikishi_debut.csv`・`hfin2026.txt`)、v19 は `patch22.py`(v18 → v19、スタート画面。画像は `img/` から読んで埋め込む)、v20 は `patch23.py`(v19 → v20、保存データの読み込みと「続きから」)、v21 は `patch24.py`(v20 → v21、ホーム画面のアイコンと更新ボタン。アイコンは `img/icon180.png`)、v22 は `patch25.py`(v21 → v22、保存・終了ボタンとスキン。色はパッチの中の表 `SK` から CSS を作る)、v23 は `patch26.py`(v22 → v23、受け持つ部屋のカード)、v24 は `patch27.py`(v23 → v24、マニフェストを読む)、v25 は `patch28.py`(v24 → v25、スタート画面の「画面の色」)、v30 は `patch33.py`(v29 → v30、決まり手と部屋の入れ替わり)、v29 は `patch32.py`(v28 → v29、伸びしろの倍率。引数で変えられる:`python3 patch32.py v28 v29 0.75 0.85`)、v28 は `patch31.py`(v27 → v28、けが・休場・不祥事の数合わせ。けがの倍率と不祥事の確率は引数で変えられる:`python3 patch31.py v27 v28 2.1 .0008`)、v27 は `patch30.py`(v26 → v27、設計 20。経歴データ `KEI` も最新のものに差し替える)、v26 は `patch29.py`(v25 → v26、経歴。データは `keireki2026.txt`・`keireki_low2026.txt`・`keireki_toshi2026.txt` を読んで `KEI`・`KEIT` として埋め込む)。
- コアの関数は画面(DOM)に依存しないので、Node の `vm` で `'use strict';` から `/* ========== 画面` の手前までを切り出して自動プレイできる。
- 画面テストは Playwright(Chromium)。
- スタート画面:`UI.start`(なし=入口、`'real'`、`'new'`)で切り替え。`topHTML` / `nightHTML` / `goStart`、入力欄は従来の `realStartHTML` / `startHTML`。入口では `body.st-top` で縦スクロールを止める。`UI.title`(起動時に保存データがあれば真)の間もスタート画面を出し、「続きから」(`goStart('cont')`)でゲームに入る。
- アプリの更新:本体の `APPV`(版の番号)と、同じフォルダの `latest.json`(`v`・`file`・`note`)を比べる(`checkUpd`)。新しければ `UI.upd` に入れ、`askUpd` → `doUpd`(保存してから `location.replace`)。**版を作るたびに `latest.json` と `APPV` を書き換える**(CLAUDE.md にも書いた)。ファイルから直接開いたときは確かめられない。
- スキン:`body` に `sk-名前` のクラスを付け、色の変数と、色を直接書いている部品(見出し・ボタン・表・入力欄など)を上書きする。`SKINS` / `applySkin` / `setSkin` / `skinPanel`。新しい部品で色を直接書くときは、スキンでも見えるか確かめる(墨の夜は暗い背景)。
- 保存・終了:`saveNow`(保存して `toast`)、`quitTop`(保存して `UI.title=true` でスタート画面へ)。
- 受け持つ部屋のカード:`heyaList`(REALH・REALB・HEYAD・HFIN・TOSHI から部屋ごとのあらましを作る。資金力と始めのお金は `finScore` と同じ式で、45 部屋すべてゲーム開始後の値と一致することを確かめた)、`realStartHTML`(カード)、`hsSet`(並べ方・一門)、`heyaSheet` / `heyaClose`(下から出る説明)。開始は従来どおり `doStartReal`(説明の中の隠し項目 `#r_h` と取り口 `#r_t` を読む)。
- ホーム画面のアプリ:iOS は、アプリの受け持ち範囲の外のページを開くと、上に方位磁針付きのバーを出す。範囲はマニフェストの `scope`(`/sumo/`)で決めている。ページの側からバーを消すことはできないので、範囲の外へ飛ばさないこと(`judge/` も範囲の中だが触らない)。
- スタート画面の画面の色:`skinSheet` / `skinPick` / `skinClose`、写真は `SKIMG`。スキンの色を変えたり増やしたりしたら、写真も撮り直して `img/skin/` を差し替える。下から出る説明を開いている間は `body.hs-open`(右下の出典を隠す)。`render` のたびに外す。
- 経歴:`KEI`(四股名 → 出身地・中学・高校・大学・社会人・アマ成績・家族・出典)、`KEIT`(親方の元の四股名 → 同じ)。`keiOf`(`r.kk` か `r.n` で引く)、`keiTOf`、`keiCard`(経歴カード)、`keiFam`(家族の四股名をリンクに)、`keiR`。力士の画面のタブは `UI.rtab`(`rTab`)、親方の画面は `showT(G.toshi の番号)` とタブ `UI.ttab`。経歴データを直したら patch29 を当て直すか、次のパッチで `KEI` を差し替える。
- 親族:`KINP`(四股名 → 血縁 4 親等以内の四股名)を `kin2` で見る(二世の父が同じ、も従来どおり)。母校:`bokou(r)`(大学を優先、なければ高校。ゲームの学校一覧にあれば関係も上がる)。新弟子の大会記録:`r.arec`(アマ時代の `a.rec` と同じもの)、表示は `keiAma`。
- テストの台本:`tests/realmatch.js`(休場・けが・不祥事の数を測る)、`tests/v27.js`(設計 20)、`tests/keireki.py`(経歴のタブ・親方の画面)、`tests/skin_start.py`(スタート画面の画面の色)、`tests/start_flow.py`(スタート画面・続きから)、`tests/skins.py`(スキン・保存・終了)、`tests/heya_cards.py`(部屋のカード)。
- 主な関数:`newGame` / `newGameReal`、`doWeek`(`aniAssign` → 稽古 → `shiteiWeek`)/ `weekR` / `bodyWeek`、`startBasho` / `advanceDay` / `fight`、場所後(`v7Basho` → `v8Basho` → `payBasho` → `v12Basho` → `v13Basho` → `v14Basho` → `v15Basho` → `amaBasho` → `retireCheck` → `genEvents`)、`nextCycle` / `computeBanzuke` / `kyuFloor`、`migrate`。
- 出来事は `EVT` にまとめてある。番付発表のあとの出来事(化粧廻し・綱打ち・改名)は稽古期間の画面に出し、初日までに答えなければ自動で決まる。
